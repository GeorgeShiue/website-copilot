# 專案概述
- 建立 AI 助手，提升現有網站在資訊量龐大或功能複雜時的使用體驗。
- 透過自動爬取、索引與檢索網站內容，提供更快速、精準的搜尋結果。
- 支援自然語言問答，讓使用者能用日常語言查詢網站內容。
- 提供來源佐證與內容摘要，降低模型幻覺並強化答案可靠性。
- 未來目標擴展至網站導航、功能控制與專責代理。

# Phase 1：資訊檢索（當前目標）
> - 痛點：使用者難以在分散的 FAQ、部落格或多層級頁面中，快速找到所需的具體資訊。
> - 解法：AI 自動爬取並索引全站內容，建立知識庫，以自然語言精準回答提問並附上來源佐證。
> - 應用場景：使用者詢問「請問教授今年還有收碩士生的名額嗎？實驗室近期的 LLM 研究方向是什麼？」AI 可立即整合招生公告與近期發表的論文重點，並提供來源連結供查閱。

## 1. 建立網站知識庫
> 提高檢索效率、降低幻覺率。
- 資料獲取：自動爬取網站內容，包含文字、結構與相關資源。
- 資料前處理：清洗、過濾並標準化網頁文本以便索引。
- 向量資料庫：建立可查詢的嵌入索引，支援語義檢索與問答 **(未完成)**。

## 2. 設計 AI Agent (未完成)
> 加強互動性、強化記憶管理。
- 意圖識別與查詢轉換。
- 工具調用與檢索策略。
- 答案評分與自我修正。
- 對話記憶管理。

## 3. 網站嵌入聊天介面 (未完成)
> 提供多種嵌入方案。
- 聊天視窗組件開發。
- 前端狀態與後端 API 串接。
- Markdown 與來源渲染。
- API 路由代理。

# 未來規劃
## Phase 2：網站導航
> - 痛點：使用者面對複雜的功能選單容易迷失方向，或不願進行繁瑣的點擊與查找操作。
> - 解法：AI 理解使用者自然語言指令後，直接控制網站介面進行頁面跳轉、資料篩選或功能切換。
> - 應用場景：使用者說「帶我去看歷屆學長姐做的多智能代理（Multi-Agent）系統展示」，AI 直接將畫面跳轉至該專案的相關頁面，省去在選單中尋找的時間。

## Phase 3：專責代理
> - 痛點：通用型回答無法解決個人帳戶的特定問題，且重複填寫複雜表單的流程容易降低使用者操作意願。
> - 解法：AI 整合使用者身分權限與歷史數據，自動完成表單代填，並透過生成式互動卡片讓使用者一鍵確認執行。
> - 應用場景：使用者說「幫我預約明天的 RTX 4060 Ti 伺服器算力」，AI 可依學生帳號權限自動填入常借用的時段與設備規格，並彈出確認卡片供使用者檢查後送出。
