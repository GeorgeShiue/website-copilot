# HTML 日期擷取

---

## 日期擷取

原先時間 metadata 僅靠文字推斷 → 改為**爬蟲階段從 HTML 結構化標籤擷取**

| 優先級 | 來源 |
|:------:|------|
| 1 | JSON-LD `datePublished` |
| 2 | OG `article:published_time` |
| 3 | `<time datetime>` 元素 |
| 4 | Generic meta `date` / `pubdate` |
| 5 | Dublin Core `dc.date` |
| 6 | HTTP `Last-Modified` |

無資料時 fallback 至原有文字推斷策略，完全向後相容。

---

## nculab / ncucsie 無法擷取日期

| 站點 | 平台 | 結果 | 原因 |
|------|------|:----:|------|
| **nculab** | Google Sites | ❌ | SPA 架構，HTML 中完全沒有 JSON-LD、OG meta、`<time>` 等結構化日期標籤 |
| **ncucsie** | 自架 PHP 站 | ❌ | 無結構化日期標籤，伺服器也不回傳 `Last-Modified` 標頭 |

> HTML 日期擷取的有效性高度依賴網站平台（WordPress、Medium 等有 SEO 套件的網站才有效）。
> 對 nculab / ncucsie，仍依賴 `MarkdownDateExtractor` 文字推斷作為主要日期來源。

# 多站 RAG 檢索工具

---

## 問題

Agent 工具層硬綁**單一 RAG 實例**，無法同時存取多站知識庫。

## 解法

| 組件 | 功能 |
|------|------|
| **RAGRegistry** | 多站 RAG 實例管理：lazy + LRU 快取（上限 5） |
| **webpage_retriever** | 新增 `site_id` 必要參數，依 site_id 路由至對應 RAG |
| **list_knowledge_bases** | 站點發現工具，回傳所有可用 site_id |

# Chrome Extension 站點偵測

---

## 自動路由

Extension 偵測當前 URL → 後端映射 → LLM 自動帶入 site_id

* `content.js` 偵測 `window.location.hostname`
* → `background.js` 透傳 `page_url` 至 Server
* → Server `resolve_site_id()` 映射為 site_id
* → `_enrich_query()` 前綴 `[使用者瀏覽 nculab 網站]` 至 user query
* → LLM 自動帶入 site_id → `RAGRegistry` 路由至正確知識庫

使用者**無感切換**——開啟哪個學校的頁面，Agent 就查哪個知識庫。

---

## 三種介面共用路由

| 介面 | site_id 來源 |
|------|-------------|
| **Chrome Extension** | `window.location.hostname` → 後端 `DOMAIN_SITE_MAP` 映射 |
| **CLI** | `--site-id` 手動指定 |
| **Server API** | 請求參數 `page_url`（可選） |

**Service Worker Keepalive**：`chrome.alarms` 每 25 秒觸發，解決切站時連線中斷問題。

# 實作成果

---

## 架構總覽

* **Chrome Extension**：`content.js` 偵測 hostname → `background.js` 透傳至 Server
* **FastAPI Server**：`resolve_site_id()` 映射 → `_enrich_query()` 注入 site 語境
* **LangGraph Agent**：多輪記憶 + SSE 串流，自動選擇 `webpage_retriever(site_id)`
* **RAGRegistry**：LRU 快取管理多站 RAG 實例 → 路由至 Milvus nculab / ncucsie
