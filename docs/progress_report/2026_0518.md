# **專案核心目標**

為現有網站導入專屬 AI 助手，解決使用者面對「資訊量龐大」與「功能複雜」時的痛點，將傳統被動的網站導覽，翻轉為主動服務的互動體驗。專案第一階段優先聚焦於**資訊檢索**能力的建置。

# **一、 專案總體執行規劃**

第一階段（資訊檢索）的開發藍圖已明確拆分為以下三個核心里程碑：
* **階段一：建立網站知識庫**（建構純淨、具備語意且可追溯的結構化資料底層）—— **📍 目前進度**
* **階段二：設計 AI Agent**（打造大腦核心，包含意圖識別與檢索決策）
* **階段三：嵌入聊天介面**（整合 UI/UX，實現網頁端的無縫上下文互動）

# **二、 目前執行進度：階段一 (知識庫建構)**

目前已完成資料處理工作流程的基礎建置，各模組的實作細節與工程亮點如下：

| 模組名稱 | 目前實作細節與技術選型 | 工程亮點與效益 |
| --- | --- | --- |
| **資料獲取 (Ingestion)** | 限制網域、深度與數量進行網路爬蟲，將網頁內容轉為 **Markdown** 格式。 | 精準去除 Navbar 與 Footer 等雜訊，僅保留內文、圖片連結與來源網址，確保資料純淨度。 |
| **圖片處理 (Vision)** | 將圖片交由 **VLM (視覺語言模型)** 進行描述，並將生成的文字回填至 Markdown 圖片位置。 | 高效的「降維打擊」策略，無需異動底層架構即可讓純向量資料庫具備「看圖」的檢索能力。 |
| **文本切塊 (Chunking)** | 依據 Markdown 語法（標題、段落）與自然語意進行 **Semantic Chunking**。 | 防禦性設計：將孤立的標題向下合併至內文，避免切出毫無上下文語意的無效區塊。 |
| **屬性管理 (Metadata)** | 將網頁來源網址、圖片連結等非文字資訊抽離，封裝為 Chunk 的 Metadata。 | 避免網址亂碼造成向量空間污染（Vector Pollution），並為未來的來源標註（Citation）打下基礎。 |
| **向量儲存 (Storage)** | 模型：OpenAI `text-embedding-3-small`資料庫：本地端部署 `Qdrant` | 模型兼具高性價比與效能；Qdrant 可完美搭配 Metadata 策略進行精準的 Payload Filtering。 |

# **三、 未來待辦事項**

針對知識庫的完善以及未來的架構演進，目前的待辦清單與中長期規劃如下：

| 發展面向 | 短期待辦任務 (Next Steps) | 中長期升級規劃 (Future Roadmap) |
| --- | --- | --- |
| **檢索精準度優化** | 執行 **語意搜尋 (Dense)** 對比 **混合搜尋 (Hybrid - Dense + Sparse/BM25)** 的成效驗證。 | 針對專有名詞或特定型號，調校混合搜尋的權重比例（Score Fusion）。 |
| **資料來源穩定度** | 暫無（持續優化現有爬蟲規則）。 | 評估直接串接後端資料庫或 CMS API，獲取結構化資料以取代前端爬蟲。 |
| **多元資料處理** | 暫無。 | 擴充資料解析能力，包含：複雜表格扁平化處理、PDF 文件解析、影音逐字稿萃取。 |
| **多模態架構升級** | 暫無（沿用 VLM 預先處理策略）。 | 評估升級為「多模態 RAG (Multimodal Embeddings)」，或改由「Agent 判斷後動態查找 VLM 讀取圖片」。 |
