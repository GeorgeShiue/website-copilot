# 查詢模組設定

## Retriever

### Top K

> **目前穩定值：5**

- 初始值是 `top_k=2`，在 `cutoff=0.6` 時容易出現 `Empty Response`
- 提升到 `top_k=5` 後，檢索到的來源數明顯增加，且在 `cutoff=0.4` 時可穩定取回內容
- 目前 `top_k=5` 已足夠支撐多數問題，單純把 `top_k` 再往上加的收益不大——針對名單型問題（如「實驗室的成員有哪些人？」）將 `top_k` 提高至 10 仍無法 recall `Members.md`，因為問題是 embedding 語義比對的局限而非 recall 不足。

## Query Engine

### LLM

> **目前穩定值：gemini 3.1 flash lite**

### Cutoff

> **目前穩定值：0.45**

- `cutoff=0.6` 會導致部分查詢（例如時間範圍題）出現 Empty Response；`top_k=5, cutoff=0.4` 為先前穩定的 baseline。
- 針對「實驗室的成員有哪些人？」實驗：將 `cutoff` 提高至 `0.45`（維持 `top_k=5`）使 retrieved sources 從 5 減至 4，Faithfulness / Relevancy 分別由 20%/10% 提升到 70%/30%。

# 5 種問題實驗 (2026/6/26)

## 實驗記錄

### 不穩定
- `實驗室近三年發表過哪些論文？`
  - 時間範圍問題表現最差，主要原因是查詢沒有被轉成明確年份範圍，且檢索混入最新消息、活動、學位論文等不同頁型
  - 將問題改成明確年份後，整體表現仍不穩，表示單純依賴 query 字面年份不足以解決問題
  - 這類問題的改善重點應放在 query rewrite、年份 / page_type metadata 路由，以及更保守的回答約束，而不是只調 `top_k` 或 `llm_name`
  - `top_k` 與 `llm_name` 仍是共通能力因素，但對時間範圍問題屬於次要影響，適合作為 baseline 調整而非專項解法
- `實驗室的成員有哪些人？`
  - **表現**：在 `top_k=5, cutoff=0.45` 下，每次 query 取回 4 個相同的 sources（皆為獲獎公告或招生頁），**`Members.md` 始終未被 recall**。`cutoff` 降至 0.4 或 `top_k` 升至 10 也無法改善，反而引入更多噪音（如 `Story_ChatBot` 歷年成員），使回答品質更差。
  - **原因**：`Members.md` 每筆成員資料夾帶大量 VLM 圖片描述文字（如「年輕男性身穿學位袍…」），語義向量偏向人物外觀／生活照主題，與「實驗室的成員有哪些人？」的 query 語義距離過遠。**問題不在 threshold，而是純向量檢索對這類結構化列表的本質局限**。
  - **對策**：導入 hybrid search（向量 + BM25 keyword）或 query expansion 改善召回；pre-processing 階段對圖片描述降權重。

### 穩定
- `實驗室在2024年有哪些活動？`
  - 觀察：`cutoff=0.5` 時，回答能聚焦在 2024 年的活動與成就，且測試結果通過 Faithfulness / Relevancy；相較較低 cutoff，回覆更少混入跨年度或無關內容。
  - 來源狀態：本次回覆主要依賴單一高相關來源，檢索到的證據足以支撐 2024 年活動摘要。
  - 注意事項：這個設定雖然對活動題表現較穩，但對其他召回較弱的查詢可能會導致 `Empty Response`，因此不適合作為全域固定值。
- `加入實驗室需要準備哪些資料？`
  - 觀察：在 `cutoff=0.45` 下，10 次測試全部通過，Faithfulness / Relevancy 皆為 100%，顯示這題有穩定且直接的來源支撐。
  - 來源狀態：回覆主要對應到 Prospective_Students 相關頁面，核心內容一致指向 CV、學業成績單、簡短研究計畫，以及申請前先閱讀研究領域與近期論文。
  - 解讀：這類申請流程題屬於高可驗證查詢，即使維持目前的 cutoff，也能穩定取得足夠證據，不需要再提高閾值。
- `如何聯絡研究室指導教授？`
  - 觀察：在 `cutoff=0.45` 下，10 次測試全部通過，Faithfulness / Relevancy 皆為 100%，顯示聯絡方式與申請流程有明確且一致的來源支撐。
  - 來源狀態：回覆主要依據 Prospective_Students 與 WIDM 實驗室歡迎頁，內容一致指向電子郵件聯絡張教授，並附帶履歷、成績單與研究計畫等申請資料。
  - 解讀：這題與「加入實驗室需要準備哪些資料？」同屬流程型問題，生成結果穩定，不需要額外提高 cutoff。

## 實驗總結

### 核心問題

RAG 的瓶頸不是單一參數，而是 **「檢索精準度 × 召回率 × 生成約束」** 三者的平衡：`cutoff` 太低易混入噪音引發過度推論，`cutoff` 太高則使召回不足的查詢變成 `Empty Response`。不同問題類型的脆弱點截然不同，需要差異化處理。

### 三種問題類型的診斷與對策

| 類型 | 範例 | 穩定度 | 瓶頸層 | 成因 | 關鍵對策 |
|------|------|--------|--------|------|----------|
| **流程型** | 加入實驗室所需資料、如何聯絡教授 | ✅ 穩定 (`100%`) | — | — | 維持現有配置即可 |
| **時間範圍型** | 近三年發表論文、2024 年活動 | ❌ 最不穩定 | 檢索 + query 理解 | query 中的時間表述（如「近三年」）未被轉為明確年份範圍；檢索混入最新消息、活動、學位論文等不同頁型；簡單將問題改為明確年份仍因頁型混雜而不穩 | query rewrite 將時間表述轉為明確年份；page_type / year metadata 路由；生成時保守回答 |
| **名單型**（原稱 roster）<br>即「成員名冊」類問題 | 實驗室的成員有哪些人 | ❌ 檢索失靈 | **檢索層為主** | `Members.md` 每筆成員資料含大量 VLM 圖片描述文字，embedding 語義偏向人物外觀／生活照主題，與查詢語義距離過遠——純向量檢索的本質局限，調大 `top_k` 或降低 `cutoff` 均無效。生成層將公告中零散人名外推為完整名單是檢索失敗的次生現象 | 導入 hybrid search（向量 + BM25 keyword）或 query expansion；pre-processing 階段對 VLM 圖片描述降權重；生成時強制 provenance 檢查 |

### 後續行動

| 優先序 | 方向 | 具體做法 | 解決的問題 |
|--------|------|----------|-----------|
| **P0** | 改善檢索策略 | 導入 hybrid search（向量 + BM25 keyword）；對特定 query 搭配 query expansion 或 page_type routing | 名單型問題的召回瓶頸、時間範圍題的頁型混淆 |
| **P1** | 生成階段約束 | 對名單型 / 時間範圍類查詢強制 provenance 出處標示，避免外推 | 生成層的過度推論 |
| **P2** | cutoff 彈性化 | 保留 `cutoff=0.45` 為預設；對低召回題型（如時間範圍題）加入降閾值或 fallback 機制 | 避免 `Empty Response`
