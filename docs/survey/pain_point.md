# 痛點一：引導流於「口頭指引」，缺乏實質之系統操作與輔助能力

目前多數網站輔助應用（如主流之 AI 客服 Widget）之功能定位仍侷限於對話式的「步驟說明」，將實際執行的認知負荷（Cognitive Load）完全轉嫁予使用者。

- **現況痛點（說明與執行之體驗斷層）：**

    當使用者提出操作流程之詢問時，AI 僅能產出冗長的文本步驟指引。使用者必須一邊閱讀對話框訊息，一邊於複雜的系統介面中搜尋對應之 UI 元件，容易導致操作中斷或錯誤。

- **成因分析：**
    1. **權限與安全壁壘：** 為確保跨網站之通用性並規避資安風險（如 XSS 跨站腳本攻擊），市售 B2B 產品通常採「唯讀（Read-Only）」策略，不介入用戶端之狀態變更。
    2. **前端架構動態性：** 現代單頁應用程式（Single Page Application, SPA）具備高度動態渲染特性，外部通用型 Agent 難以透過單一 CSS 選擇器精準捕捉並觸發事件。
- **技術突破點：**

    由「被動問答角色」轉型為「主動導航與執行體」。提供前端視覺化互動引導（例如動態高亮當前介面之目標元件），並在獲得使用者授權後，透過底層 API 或控制腳本直接代為完成繁瑣的表單填寫與提交流程。


# 痛點二：過度依賴「即時感知」，缺乏對網站架構之先驗認知

現行的 Web Agent 框架主要依賴「反應式（Reactive）」之即時感知策略，於實際應用中面臨嚴峻的效能與經濟成本瓶頸。

- **現況痛點（缺乏全局地圖之反應式架構）：**

    Agent 增進對網站理解之手段，主要仰賴執行期（Runtime）的 DOM 樹解析或即時網頁截圖。此架構如同缺乏地圖的導航系統，僅能依賴局部視野進行推斷。

- **成因分析：**
    1. **高延遲與 Token 成本爆炸：** 每次互動皆須將龐大的網頁 DOM 結構或高解析度圖片反覆傳輸予多模態模型（VLM）推理，導致回應時間（Latency）過長且運作成本高昂。
    2. **缺乏全域邏輯（Global Context）：** 即時爬蟲無法理解隱含於介面背後的系統架構與業務邏輯。面對結構複雜、歷史悠久或具備舊有 CMS 的網站系統時，Agent 僅具備前端元件感知，無法得知操作對後端資料庫或跨頁面路由產生的連帶影響。
- **技術突破點：**
將『即時畫面感知』與『預建知識庫』解耦。於 Copilot 導入特定網站前，預先構建完整的網站知識地圖（包含路由架構、業務專有名詞、頁面關聯性）。於執行期間，Copilot 僅需輕量級感知當前之 URL 路由、前端狀態變數（State）或特定 API 回傳值，即可精準調用先驗知識，大幅降低推理延遲並優化操作精準度。

# 專案核心價值

本專案的核心技術價值在於**以預建之網站全域知識地圖，驅動前端即時的網頁引導與自動化操作（Action-oriented Execution）**。專案策略性地捨棄了傳統 Web Agent 追求的通用性，轉而追求與特定網站的深度融合，藉此提升操作精準度。這讓 Website Copilot 不再只是外掛於網頁角落的被動問答機器人，而是成為深度嵌入網站生態、具備系統全局視角的專屬導航與自動化操作助理。
