# 📊 目前執行進度：階段一 (知識庫建構)

## ✅ 已完成資料處理工作流程基礎建置

| 模組名稱 | 實作細節與技術選型 |
|---------|-------------------|
| **資料獲取 (Ingestion)** | 限制網域、深度與數量進行網路爬蟲，將網頁內容轉為 Markdown 格式 |
| **圖片處理 (Vision)** | 將圖片交由 VLM 進行描述，並將生成的文字回填至 Markdown 圖片位置 |
| **文本切塊 (Chunking)** | 依據 Markdown 語法與自然語意進行 Semantic Chunking |
| **屬性管理 (Metadata)** | 將網頁來源網址、圖片連結等非文字資訊抽離，封裝為 Chunk 的 Metadata |
| **向量儲存 (Storage)** | 模型：OpenAI text-embedding-3-small<br>資料庫：本地端部署 Qdrant |

---

# 🌟 工程亮點與效益

## 資料獲取 (Ingestion)

```
✅ 精準去除 Navbar 與 Footer 等雜訊
✅ 僅保留內文、圖片連結與來源網址
✅ 確保資料純淨度
```

## 圖片處理 (Vision)

```
🎯 高效的「降維打擊」策略
🚀 無需異動底層架構
👁️ 讓純向量資料庫具備「看圖」檢索能力
```

## 文本切塊 (Chunking)

```
📝 防禦性設計：將孤立的標題向下合併至內文
⚡ 避免切出毫無上下文語意的無效區塊
💡 提升檢索準確度
```

## 屬性管理 (Metadata)

```
🔒 避免網址亂碼造成向量空間污染
📌 為未來的來源標註 (Citation) 打下基礎
🎯 支援精確的 Payload Filtering
```
