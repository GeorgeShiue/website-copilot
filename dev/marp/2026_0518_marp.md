# 專案進度報告
## 為現有網站導入專屬 AI 助手

**日期：2026 / 05 / 18**
第一階段重點：資訊檢索能力建置

---

## 專案核心目標

將傳統被動的網站導覽，轉換為主動服務的互動體驗，優先解決兩個痛點：

- 資訊量龐大，難以快速找到重點
- 功能複雜，使用者不容易掌握操作方式

目前的策略是先把「資訊檢索」做扎實，再往 AI Agent 與聊天介面延伸。

---

## 整體執行規劃

第一階段已拆成三個核心里程碑：

1. 建立網站知識庫
2. 設計 AI Agent
3. 嵌入聊天介面

目前的進度集中在第一階段，目標是先完成可追溯、可檢索、可擴充的資料底層。

---

## 第一階段現況

知識庫建構的基礎流程已完成，並形成可持續迭代的資料管線：

- 網頁內容已轉為 Markdown，降低雜訊干擾
- 圖片資訊已轉成文字描述，保留視覺語意
- Chunk 以 Markdown 與語意切分，避免切碎上下文
- 來源網址與圖片連結已抽離成 Metadata
- 向量資料庫已採用本地 Qdrant 儲存

---

## 資料處理流程

### 1. 資料獲取
- 限制網域、深度與數量進行爬蟲
- 轉成 Markdown 後保留內文、圖片連結與來源網址
- 有效去除 Navbar、Footer 等干擾內容

### 2. 圖片處理
- 交由 VLM 生成圖片描述
- 將描述文字回填到原本圖片位置
- 讓純向量資料庫具備看圖檢索能力

---

## 結構化與儲存策略

### 3. 文本切塊
- 依 Markdown 標題與段落做 Semantic Chunking
- 將孤立標題向下合併至內文
- 避免產生缺乏上下文的無效區塊

### 4. 屬性管理
- 網址、圖片連結等非文字資訊改放在 Metadata
- 降低 Vector Pollution 的風險
- 為未來 Citation 與來源標註預留空間

### 5. 向量儲存
- Embedding 模型：OpenAI text-embedding-3-small
- 資料庫：本地部署 Qdrant
- 搭配 Metadata 可做精準 Payload Filtering

---

## 技術亮點

- 純淨資料底座：先清理再向量化，提升後續檢索穩定度
- 視覺降維策略：用 VLM 把圖片轉成可檢索文字
- 語意導向切塊：保留內容完整性，而不是只切字數
- 結構化 Metadata：為追溯、引用與篩選打基礎
- 本地 Qdrant：兼顧成本、效能與可控性

## 當前結論

第一階段的重點不是先做最炫的介面，而是先把知識庫做成可靠的檢索基礎。

接下來的開發方向，會以檢索精準度與資料來源穩定度為優先，逐步推進到 AI Agent 與聊天介面整合。
